# VOID SIGNAL · 虚空信号

## 安装

Node.js 22.12 或更新版本。

```sh
npm ci
```

## 本地启动

```sh
npm run dev
```

打开终端显示的本地地址。

## Docker 启动

```sh
docker compose up --build
```

打开 http://localhost:8084 。可通过 PORT 环境变量修改端口。

## 每日挑战

每日挑战由 **日期 + 挑战码** 生成，二者共同决定敌潮、可选强化、武器候选、
掉落概率与场地限制，并把 **规则版本与种子一起固定**，因此同一挑战码在任何
机器、任何版本更新后都会还原为同一局，而不是套用当前平衡参数。

### 生成与分享

- 打开「每日挑战」终端，输入本地日期（`YYYY-MM-DD`）与挑战码。
- 终端会展示完整约束（波次、武器候选、掉落概率、场地、可选强化、种子）与
  一段自校验分享码 `VS1.<payload>.<checksum>`，整段发给好友即可。
- 挑战约束会解析为一份完整、不可变的规则快照挂在本局上，不可能只改标题。

### 导入与复核

- 导入损坏挑战码（格式错误、校验和不符、字段越界）会被标记为 `corrupt`，
  当前行动完全保留，不会被替换或打断。
- 结构合法但规则版本不被当前客户端支持时标记为 `unsupported`，与损坏区分开。
- 重复加载同一挑战码总是从零开始，绝不继承上一局的武器与强化。
- 跨天时进行中的挑战继续使用开局时固定的规则快照，不受系统日期影响。
- 结算时可导出复核 JSON。好友本地复核会校验种子与约束的一致性，并把结果
  区分为「撤离成功（已验证）」「真实失败（已验证）」「规则版本不受支持」
  或「结果损坏/被篡改」，真实失败与版本不受支持不会混淆。

### 架构

- `src/shared/rules.ts`：版本化的完整平衡快照（`RulesetV1`）与校验逻辑。
- `src/features/challenges/`：挑战生成、分享码编解码、规则派生、结果复核。
- 引擎各 step 只读取 `doc.rules`，不再依赖模块级平衡常量。
